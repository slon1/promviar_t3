# Накопление материала на поверхности

Unity 6 (URP). В Play Mode на процедурной сетке копится реальная геометрия Mesh:
зона ездит по WASD, радиус пульсирует, по удержанию Space вдоль следа растёт
полусферический купол. Состояние материала живёт в heightmap, не в вершинах.

## Хранение материала

`MaterialHeightmap` держит `NativeArray<float>` высот в **surface-local** XZ
(object space поверхности). Класс не знает про `Mesh` и `Transform`. Индексация
`ix + iz * Width`. Inspector `_resolutionX/Z` — число квадов; вершин на одну
больше (дефолт 128×128 квадов → 129×129 вершин, плоскость 20×20).

## Обновление Mesh

`SurfaceMeshSync` копирует высоты в переиспользуемый `NativeArray<float3>` и
публикует их через `Mesh.SetVertices` / `Mesh.SetNormals` (без managed-массивов
на кадр). Нормали считает отдельный Burst `IJobParallelFor` конечными разностями
по четырём соседям, не `Mesh.RecalculateNormals()`. После записи вершин
вызывается `Mesh.RecalculateBounds()`.

Синхронизация идёт только когда высоты реально могли измениться: после
`AccumulationJob` внутри `if (Accumulate.IsPressed())`, плюс сразу в
`ResetSurface()`. Пока Space не зажат, Mesh не трогается.

## Алгоритм накопления

За кадр материал добавляется вдоль отрезка предыдущая позиция → текущая
(swept-capsule), а не точечно в центре зоны — след не рвётся на низкой частоте
кадров. Высота монотонно растёт (`max`) и за один вызов не превышает полусферу
от плоскости `Y = 0` (`capLocal`) и не прыгает быстрее `rate * dt`.

Активация — удержание Space. Радиус пульсирует по `AnimationCurve` всегда,
даже без накопления.

## Как запустить

1. Открыть `Assets/Scenes/SampleScene.unity`.
2. Play. Объект поверхности — `MaterialSurface`.
3. Управление:
   - WASD / стрелки — движение зоны;
   - удерживать Space — накопление;
   - R — сброс поверхности в плоскость (`ResetSurface()` можно вызвать и из кода).
4. Тесты: Window → General → Test Runner → EditMode, сборка
   `MaterialAccumulation.Tests`.

Стек: Burst, Collections, Mathematics, Input System. Zenject / UniTask / DOTween
в решении не используются.

## Ограничения

- Накопление и нормали — CPU Jobs + Burst, не GPU compute. Дефолтная сетка
  129×129 за кадр дешёвая; при росте разрешения в разы упрётесь в бюджет 60 FPS
  на CPU раньше, чем в fillrate.
- Нормали — finite-difference по четырём соседям. Дёшево и без аллокаций, но на
  острых перегибах менее гладко, чем area-weighted `Mesh.RecalculateNormals()`.
- Heightmap не сохраняется между сессиями.
- Зона двигается в осях surface-local XZ, не относительно камеры.
- Индексы Mesh — `UInt32`; практический предел — CPU Job, не формат индексов.
- На первом `Schedule` Burst Job Unity может один раз предупредить, что generic
  обёртка ещё не зарегистрирована как entry point. Job при этом выполняется;
  пакет `com.unity.jobs` сознательно не подключали.

## Возможные улучшения

- Отдельный Job сглаживания / эрозии высот для более органичного вида.
- Чанкование / LOD heightmap, если понадобится большая поверхность.
- GPU compute при разрешениях, где CPU уже не держит 60 FPS (потребуется
  readback, если вершины должны остаться на CPU).
- Сериализация `NativeArray` высот в файл.
- Ввод относительно камеры, а не осей поверхности.
